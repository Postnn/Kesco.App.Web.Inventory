# Телефонный номер — руководство пользователя

Форма открывается из запроса **1012 «Телефонные номера»** либо напрямую по адресу `/Telefon/Tel?id=<ID>`. Для совместимости со старыми ссылками поддерживается `/Telefon/Tel.aspx`. Создание доступно по `/Telefon/Tel`, копирование — по `/Telefon/Tel?copyId=<ID>`.

## Команды

- **OK** — сохранить запись и закрыть форму.
- **Применить** — сохранить запись и оставить форму открытой. После создания форма переходит в режим редактирования нового ID без перезапуска страницы.
- **Копировать** — открыть новую форму с простыми полями текущего номера. ID, история изменения и связанные коллекции не копируются.
- **Удалить** — после подтверждения удалить номер и его связи. Если от номера зависят ведомые или отображаемые номера, удаление запрещено.
- **Обновить** — повторно прочитать запись. При наличии несохранённых изменений требуется подтверждение.
- **Отмена** — закрыть форму; несохранённые изменения также требуют подтверждения.

Для изменения нужна роль **43 «Специалист по инвентаризации оборудования»**. Роль проверяется сервером при записи, а не только видимостью кнопок.

## Основные поля

- Номер — строка до 4 символов: цифры, `#`, `*`; ведущие нули сохраняются.
- Полный номер предварительно вычисляется формой и повторно проверяется сервером по актуальным зависимостям, окончательное значение назначает триггер БД.
- Тип фильтруется выбранной станцией. Станция намеренно не фильтруется обратно по типу: несовместимый выбор показывает ошибку вместо скрытия значения.
- Порт АТС обязателен, если для выбранных типа и станции существуют порты. В списке есть свободные порты и собственный текущий порт.
- Группа перехвата: для CCM используются именованные значения `pickupGroups` из `web.config`, для станций 1–99 — значения `0..15`.
- Переадресация и автонабор могут содержать `+`, цифры, `#`, `*`.
- Обязательны заказчик и хотя бы одно из полей «Сотрудник» / «Подключено».
- Описание АТС заполняется латиницей. Кнопка рядом с полем формирует его по сотруднику; станция может требовать верхний регистр. Ручной текст фоновыми изменениями не перезаписывается.
- «Основной номер» доступен при выбранном сотруднике. Если номер был скрыт из справочника или режим ещё не выбран, при установке признака включается отображение; другие выбранные режимы сохраняются.
- Срок возврата включается отдельным чекбоксом и не может быть в прошлом.

При выборе сотрудника подставляется его организация в поле заказчика. Предупреждения о несоответствии заказчика работодателю или владельцу номера переадресации показываются, но не блокируют сохранение, как в legacy. Ошибки формата, дубликаты, недопустимые связи и отсутствие обязательных данных блокируют сохранение.

## Связанные списки

Все действия ниже меняют **черновик** и записываются только общей командой **OK** или **Применить**.

- **Параллельные вызовы:** секция находится после номера автонабора. Номер можно добавить быстрым вводом/Enter либо через диалог. Поддерживаются две задержки от 0 до 255 и признак «Не использовать». Дубликаты и самовызов запрещены. При наличии вызовов номер должен отображаться в справочнике.
- **Члены группы:** доступны для PBX-группы. Нельзя добавить текущий номер, дубликат или номер с другой станции.
- **Входит в группы номеров:** отдельный read-only список обратных связей с переходами к группам.
- **Оборудование:** добавляется из бизнес-фильтра по типу, станции, сотруднику и розетке. Одно оборудование можно связать с номером только один раз; смена оборудования подключения выполняется как точная замена связи. Поддерживаются другие номера, срок возврата и примечание. Просроченные сроки подсвечиваются.
- **Срок возврата оборудования** редактируется кнопкой с часами в соответствующей строке и не затрагивает другие связи.

Смена номера с непустыми параллельными вызовами, станции с непустой PBX-группой или типа с оборудованием требует подтверждения. При отказе прежнее значение и коллекции сохраняются.

## Несовместимые значения

Если после смены типа или станции прежнее значение перестало поддерживаться, оно остаётся видимым в read-only с предупреждением. Оно не исчезает молча. Перед сохранением форма перечисляет значения, которые будут очищены; при отмене сохранение и очистка не выполняются.

## Сохранение и АТС

Основная запись и изменённые связи сохраняются одной SQL-транзакцией. Неизменённые связи повторно не записываются. Структурное добавление, удаление или замена оборудования также запускает синхронизацию текущей станции; изменение только срока или примечания её не запускает.

Процедура Xorcom читает текущую запись по идентификатору номера. Поэтому при смене Xorcom-станции старая АТС очищается **до** SQL Save, а новая настраивается после него. Перед этой предварительной очисткой выполняется read-only бизнес-валидация; при SQL Save все проверки обязательно повторяются. Итоговый план синхронизации пересчитывается после SQL Save с учётом авторитетного полного номера, а уже выполненная очистка старой Xorcom не повторяется. При удалении очистка Xorcom также выполняется до удаления записи. Непосредственно перед Delete форма перечитывает сохранённые телефон, станцию и связи; несохранённый черновик в план не попадает. Если последующий SQL Save/Delete не выполнен, форма пытается восстановить номер на прежней АТС и сообщает об ошибке восстановления отдельно. Остальные операции Meridian, Xorcom и CCM выполняются после фиксации транзакции. Ошибка авторитетного расчёта полного номера отменяет Save без SQL-записи и не заменяется коротким номером.

Если синхронизация после сохранения не удалась, данные уже сохранены, форма остаётся открытой и сообщает об ошибке. Повторное **Применить** повторяет только неуспешные операции синхронизации, без повторного INSERT/UPDATE основной записи и без повторения уже успешных команд. Не закрывайте форму и не перезагружайте страницу браузера до успешного повтора. При закрытии, переходе или удалении с такими pending-операциями форма предупреждает: «Данные уже сохранены в БД, но синхронизация АТС не завершена. При закрытии повтор из этой формы будет недоступен; потребуется ручная синхронизация». Если после сохранения появились новые несохранённые правки, при закрытии или переходе дополнительно указывается и их потеря. Подтверждение удаления всегда содержит явный вопрос об удалении номера и его связей. Кнопка **Обновить** сохраняет pending-операции в текущем circuit и запрашивает подтверждение только для сброса нового черновика. Если Blazor circuit уже разорван, используйте legacy-форму или регламентную синхронизацию администратора АТС: список незавершённых операций между circuits не сохраняется.

После сохранения родительский грид обновляется через существующий callback без `location.reload`, с сохранением его состояния.
