# EquipmentForm — матрица соответствия legacy

Источники: `Equipment_form.aspx(.cs)`, `Kesco.Equipment.js`, `ModelEquipment.cs`, `TypeEquipment.cs`.
Проверяется фактический текущий код Clayzor, а не исходная версия из задания. Статус «изменено» требует
профильного теста; «подтверждено» означает, что условие найдено в исходниках и сохранено.

## Основные поля

| Элемент | Правило legacy | Состояние / целевое поведение Clayzor | Проверка |
|---|---|---|---|
| SN | Обязателен только при выбранной модели и `IsSnRequired` типа | Изменено: `HasSelectedModel && IsSerialNumberRequired` | bUnit: типы с требуемым/нетребуемым SN, модель отсутствует |
| Списание | Дата, время и документ; документ списания ограничен актом списания | Восстановлен точный фильтр 2365; предложения существующих актов требуют подтверждённого DocView URI | SQL источника, UTC/DST; ссылки пока не реализованы |
| Тип | Обязателен; сортировка по ID или алфавиту | Подтверждено; смена типа сбрасывает модель, временный ввод не должен уничтожать данные | ClaySelect + EquipmentForm |
| Модель | Тип фильтрует поиск только если выбран; модель без типа устанавливает тип | Изменено: nullable SQL-фильтр и автоматическая установка типа | Источник без типа, смена/очистка/Escape, гонки |
| Характеристики модели | `RenderModelData`: PN, мультимедиа, диагональ, CPU, Net/NetName, память/банки, драйвер, ресурс, примечание | Изменено: полные поля в одном SQL-запросе и Razor | Маппинг и фактическая разметка |
| Телефонные номера | Блок показывается только при выбранной модели и телефонном признаке типа | Изменено: `HasSelectedModel && HasPhoneNumber` | bUnit: модель отсутствует/выбрана |
| Видеокамера | Только тип 30 внутри телефонного блока | Изменено: `ShowPhones && TypeId == 30`; monitor-признак не используется | IP-телефон и монитор другого типа |
| Пул телефона | Только тип 30 внутри телефонного блока | Изменено аналогично камере | IP-телефон и другой телефонный тип |
| Сетевое имя | При выбранной модели и `ExistNetworkName` типа | Изменено: оба условия | Модель отсутствует/выбрана |
| MAC / MAC 2 / MAC ILO | Маска модели: Net 0/1/2/3+; без модели полей нет | Существующий `min(3, Net)` сохранён и ограничен выбранной моделью | Теория Net=0/1/2/3+ |
| Примечание | Всегда редактируется при общем праве | Подтверждено | Сохранение основного UPDATE |
| Должность | `DBSPosition` только при SIM-характеристике; не входит в основной UPDATE | Отсутствует; источник и назначение требуют отдельного подтверждения | Запрещено выдумывать поле записи |
| Владелец | Обязателен; фильтрует документ поступления и влияет на роли | Восстановлено: смена фильтра не очищает документы/поставщика; очистка владельца сбрасывает фильтры и права | Изменение/очистка владельца, права |
| Арендатор | `dbsTenant.IsReadOnly = true` | Восстановлено: поле read-only независимо от `_canEdit` | ReadOnly при любой роли |
| Документ поступления | Фильтр владельца; единственное отличное лицо документа подставляется поставщиком | Подтверждено; выбранное значение восстанавливается по ID вне поискового фильтра | Поздний ответ и ручной выбор поставщика |
| Поставщик | Редактируемое лицо; автоподстановка не перекрывает более поздний ручной выбор | Подтверждено | bUnit/гонка |

## Секции и сводные сведения

| Секция | Условие legacy | Состояние / целевое поведение Clayzor | Проверка |
|---|---|---|---|
| Телефоны | Телефонный признак и выбранная модель; серверные фильтры и исключение текущих ID; условные колонки подключения/срока | Видимость и фильтры восстановлены; состав колонок, ссылки и выделения — этап 5 | Пустой/один/несколько номеров, параметры поиска |
| Учётные записи | MAC-характеристика и роль дежурного инженера; секрет отдельно | Восстановлено: MAC+102 для чтения, 102+43 для записи; сервер повторно проверяет роли | Роль, тип, отказ без прав |
| Маршрутизатор | Действительная запись `EQ.Router`; read-only описание и модули | Условие по данным сохранено; описание есть | Есть/нет данных |
| SIM | `IsCharacteristicsSim`; одна запись: добавление либо редактирование/удаление | Добавление блокируется при существующей записи; запись требует серверную роль 42 | Нет/есть SIM, отказ без роли |
| Дополнительные услуги SIM | SIM-характеристика; история и обязательные услуги; плановые поля по контракту | Базовый CRUD и серверная роль 42 есть; условные колонки — этап 5 | Фильтры, даты, пересечения |
| Лицензия | `IsCharacteristicsSoft`; роль по владельцу/арендатору | Повторное добавление блокируется; роль 44 пересчитывается при смене владельца и проверяется сервером | Роль 44, смена владельца, отказ без роли |
| Компьютер | `IsCharacteristicsComputer`; динамические RAM/HD/SSD и конфигурации | Требует этапа 5: текущие колонки общие; запись проверяет роль 43 | Разное число компонентов |
| Расположения | Всегда; «На руках» при отсутствии ответственного создаёт обе записи | Подтверждено и покрыто тестом из EquipmentForm; серверная роль 43 | Пустой/выбранный сотрудник, SQL-ошибка |
| Ответственные | Всегда; выдача/изъятие/изменение без удаления истории | Подтверждено; сервис получает копию и проверяет роль 43 до SQL | SQL-ошибка, связанный refresh |
| Установленное ПО | `IsCharacteristicsComputer`, независимо от лицензионного признака | Разделено с блоком лицензии; серверная роль 43; ссылки — этап 5 | Компьютер без Soft и наоборот |
| Бухгалтерия | Секция чтения не скрывается отсутствием права записи | Восстановлено: данные видны всегда, команды доступны только при `_canUseAccounting` | Чтение без роли записи |
| UPS | Чтение связей отдельно; команда для IT (`TypeId<100`), не SIM, роль по владельцу; сводка вверху | Условия, серверные проверки и фильтр офиса восстановлены; сводка вверху — этапы 5/6 | Права, фильтр расположения, отказ без роли |
| Последняя инвентаризация | Верхняя read-only сводка: дата, сотрудник, примечание, неисправность, расхождение | Данные есть внизу; название расположения/ссылка и место — этапы 5/6 | DOM и форматирование |

## Жизненный цикл состояния

- `ShowAdvGrids` вычисляет исходные секции по сохранённому типу и реальным данным.
- `DisplayAndRequiredTypeFields` реагирует на подтверждённый черновик типа/модели для основных полей.
- `ModelId` и подтверждённый объект модели раздельно управляют видимостью; backup ClaySelect сохраняется для Escape.
- Поисковый ввод не является бизнес-подтверждением. Поздние SQL/JS-ответы проверяют версии и ID.
- Права чтения, права записи и очистка скрытых значений вычисляются раздельно.
